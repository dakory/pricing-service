# Сбор цен и доступности конкурентов Airbnb

## Цель

Система собирает публичную календарную доступность и гостевые цены объявлений
конкурентов, привязанных к pricing group. Данные используются как рыночный
сигнал pricing engine. Первая версия работает с Airbnb, IDR и запросами для
четырёх взрослых.

Сбор разделён на два независимых этапа:

1. один календарный запрос получает доступность примерно на год;
2. backend выбирает нужные интервалы, после чего Lambda получает котировки цен
   небольшими батчами.

Lambda извлекает исходные факты. Выбор режима, построение интервалов и расчёт
цены конкретной даты принадлежат backend.

## Календарные данные

Для каждого дня сохраняются только:

```json
{
  "stay_date": "2026-08-03",
  "bookable": true,
  "min_nights": 1
}
```

`bookable` берётся из одноимённого поля календарного ответа Airbnb. Значение
`null` приводится к `false`. Для `bookable=true` значение `min_nights`
обязательно и должно быть не меньше единицы. Недоступные дни также сохраняются:
они нужны для оценки доступности конкурентов. Отсутствие наблюдения нельзя
считать недоступностью.

## Режимы сбора цен

Бизнес-дата определяется в `Asia/Makassar`.

### Точный режим

Применяется ежедневно к датам от текущей даты до `today + 60 дней`
включительно.

Для целевой даты `D` и `N = minNights(D)`:

1. При `N = 1` запрашивается `D → D+1`:

   ```text
   price(D) = total(D → D+1)
   price_method = single_night
   ```

2. При `N > 1` сначала проверяется непрерывно доступный левый отрезок:

   ```text
   S = D − N
   long  = total(S → D+1)
   short = total(S → D)
   price(D) = long − short
   price_method = quote_difference_left
   ```

3. Если левый отрезок недоступен, проверяется правый:

   ```text
   E = D + N + 1
   long  = total(D → E)
   short = total(D+1 → E)
   price(D) = long − short
   price_method = quote_difference_right
   ```

4. Если обе разностные пары невозможны, используется минимальный stay:

   ```text
   price(D) = total(D → D+N) / N
   price_method = minimum_stay_average
   ```

Каждый используемый интервал должен состоять из непрерывно бронируемых дней.
Если невозможно получить даже минимальный stay, доступность дня сохраняется,
а цена остаётся `null` с датированной ошибкой котировки.

### Грубый режим

Применяется раз в месяц к датам дальше `today + 60 дней` до конца доступного
календарного горизонта.

- при `N = 1` используется `single_night`;
- при `N > 1` используется `minimum_stay_average`;
- разностные пары не запрашиваются.

## Семантика цены

Источник цены — `TOTAL` из успешного `stayCheckout` response. Используется
`amountMicros`, а не локализованная строка. IDR-сумма равна
`amountMicros / 1_000_000`.

Дополнительные сборы, налоги и акции отдельно не выделяются. Текущий `TOTAL`
считается гостевой ценой выбранного stay. Предполагается, что постоянное влияние
сборов и `minNights` внутри объявления в основном сократится при последующей
нормализации относительно истории этого объявления.

Все запросы production-сборщика используют:

```text
adults = 4
children = 0
infants = 0
pets = 0
currency = IDR
locale = en
```

## Оркестрация

```text
Backend создаёт run
  → Lambda operation=calendar
  → календарный callback
  → backend сохраняет все дни и строит quote plan
  → Lambda operation=quotes, один или несколько малых батчей
  → quote callbacks
  → backend атомарно рассчитывает и сохраняет цены
  → run завершается succeeded / partially_succeeded / failed
```

Одна price-котировка идентифицируется комбинацией:

```text
listing_id + check_in + check_out + adults + currency
```

Одинаковые интервалы внутри run запрашиваются только один раз. Quote-батч должен
быть достаточно мал, чтобы гарантированно укладываться в Lambda timeout. Размер
батча задаётся конфигурацией, а не константой бизнес-логики.

## Ошибки и целостность

- структурно невалидный календарь завершает календарный этап ошибкой;
- ошибка отдельной котировки не удаляет календарные наблюдения и успешные цены;
- callback полностью валидируется до записи своей части результата;
- повторный callback идемпотентен;
- арифметический результат разности должен быть положительным;
- неизвестная валюта, неверный listing, несовпадающие даты или неизвестная
  структура считаются ошибками;
- scraper failure никогда не останавливает pricing engine: он использует
  последние пригодные данные либо исключает просроченный рыночный сигнал.

## Расписание

- календарь всех объявлений: ежедневно;
- цены ближайших 60 дней: ежедневно;
- цены дальних дат: раз в месяц;
- ручной запуск и `force_refresh`: через dashboard;
- автоматические работы сериализуются с учётом ограничений Lambda.

## Не входит в первую версию

- классификация дополнительных сборов;
- автоматическое устранение влияния налогов и cleaning fee;
- произвольный поиск anchor за пределами левой и правой формул;
- расписание с высокой частотой;
- обход CAPTCHA, ротация IP и механизмы уклонения от ограничений источника;
- нормализация цены относительно собственной истории объявления — это
  отдельный следующий этап pricing engine.
